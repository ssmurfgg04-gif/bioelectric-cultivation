## Landed (4)

1. **PERF (high) — `step()` recomputed `A.sum(axis=1)` every step.**
   `GraphCollective.A` is fixed after construction (`amputate` touches
   V/theta only; no method and no landed experiment writes `A`), so the
   Laplacian row sums are a per-instance constant that was recomputed as
   an O(n²) reduction on *every* step of the project's hottest loop.
   Now cached once at init (`self._A_rowsum`); the floats are identical
   (the same deterministic reduction). Verified: the full suite green +
   the exp304 deposit re-run byte-identical.
2. **SAFETY/TESTS — the combined deposit + safety sweep**
   (`tests/test_deposits_and_safety.py`, 5 tests in one file — the
   "combine tests where it can" directive): D1 deposit-fingerprint
   integrity across all 34 fingerprinted deposits; D2 the frozen-era
   wall-clock key scan (exp288+); D3 a repo-wide token-literal scan;
   D4 the tracked-deposit guarantee; D5 the classify vectorization's
   bit-equality test.
3. **SAFETY — 58 untracked deposits recovered.** The D4 test found 58
   main deposits (the exp1–exp133 era and the early banks) that
   predated the `results/` gitignore's `git add -f` discipline and were
   NOT in git — a sandbox revert would have destroyed them. All added
   and committed. This was a real loss-prevention catch, not a
   hypothetical.
4. **PERF/MAINT — `classify_vectorized` landed**
   (`cultivation/substrate/graph.py`): the O(n) roll-based boundary
   mask + the vectorized degree accumulation, bit-equal to the house's
   reference loop form (asserted over a fixed graph battery). The
   landed experiment bodies stay byte-frozen; this is the single shared
   implementation for any future consumer.

## Found and disclosed, deliberately not patched (6)

5. **exp288's deposit fingerprint does not reproduce from the parsed
   file** — the deposit was regenerated by its deterministic re-run
   after the body-fix commits; the in-memory → JSON round-trip type
   coercions make the stored fingerprint non-recomputable from the
   parsed file. Every fingerprinted deposit from exp289 onward
   reproduces bit-exactly (D1's pre-named exception set: exactly
   exp288). Historical, not a live hole.
6. **Machinery duplication across exp302/303/304** (~700 lines: the
   rebuild, classify, the walk, the replay). The honest reason not to
   refactor: the bodies are byte-frozen by the pre-registration pins and
   the deposits assert bit-exactness. A shared module is the FIRST item
   for any future work.
7. **`_target_of` recomputes `labeling_bfs_n` + `spec_target_n` per
   transport call** in exp303/304 (260+ recomputations of an O(n) BFS).
   Cacheable; frozen bodies.
8. **`_replay` recomputes `star_dt` per call** (exp303/304). Cacheable;
   frozen bodies.
9. **`set_floor_seen` is recorded but never asserted** (exp302/303/304)
   — a dead recording; frozen bodies.
10. **The test suite is deliberately serial** — the module-level floor
    pins make pytest-xdist unsafe. A deliberate no, not an omission;
    documented here so it is not "fixed" blindly later.
